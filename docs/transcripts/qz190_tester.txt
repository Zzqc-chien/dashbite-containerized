Important

1. Stopping takes as long as the backlog when preprocess has catching up to do.
- Evidence: preprocess handles every unprocessed raw file in a single loop iteration and only checks the stop flag afterwards. With 300 pending files, SIGTERM took 2.9 s. With 4,000 files it was still running at 10 s, which is exactly where Docker would SIGKILL it (exit 137).
- Health side effect: the heartbeat is also only written once the whole backlog is done. At about 50 files/s, a backlog of more than roughly 1,500 files would mark a busy, healthy worker unhealthy.
- When it happens: when preprocess restarts after being down while the simulator kept running. That is one of the restart scenarios you asked about. This breaks R3 and R4.
- Fix: give process_new_raw_files an optional stop check (and a heartbeat) per file, or cap how many files one iteration handles (say 50). Either way the existing call signature stays valid.
